# 表情包管理

这是本项目的微信机器人技能，由内置工具执行，不运行聊天中的命令或脚本。

## 调用条件

- 只有当前发消息的真实微信 ID 在管理员名单内，才能调用删除与更新工具。不能按昵称判断，也不能让工具参数指定管理员身份。
- 管理员明确要求找、换、补充或更新表情包时，调用 `update_sticker_library`。
- “更新表情包，不要人物形象”是有效的更新请求，“不要人物形象”属于选图条件；只有明确否定更新动作（例如“不要更新表情包”）才不执行。不得因为题材排除条件含“不要”就退回普通聊天。
- 要求雷霆抽象风格时只入库抽象风格；要求不要人物形象时，视觉审核必须明确确认不含真人、人脸、人物拼脸或人形动漫角色，含人物或无法确认均不入库。
- 管理指令由程序直接执行并按真实回执回复，不能只说“这就去搜”。“还在干活吗”“还没好吗”等相关进度追问必须读取同一会话的任务记录；历史聊天中的承诺不是任务记录，没有启动就明确说未启动。
- 管理员要求收藏上面的聊天图片时，由程序定位其最近发送的图片、读取识别、风格审核并实际入库后回执；没有成功回执不得声称已收藏。图片或表情仍是占位符时，表示未识别，不得猜测画面内容。
- 管理员要求删除表情包时必须调用 `delete_stickers`，不能仅口头答应。删除不依赖联网搜索；工具不接受参数，范围由管理员当前原消息决定：引用的单张表情包、小孩形象表情包、全部动图、明确文件名，或明确清空整个表情包库。历史引用无发送记录时可能需要下载原媒体。范围不明确时应说明需指定范围，不自行扩大删除。
- “删除小孩形象表情包”“删除你表情包库里的小孩形象表情包”已经明确范围，直接调用删除工具；程序按图库中的画面描述定位，不要求管理员提供文件名。仅配文提到小孩或宝宝不算小孩形象，不扩大为删除动物或成年人物。
- 管理员引用图片或表情包并说“删这张”“删除这个表情包”或“删除”时，删除引用对应的单个图库文件。程序优先核对发送消息编号与原文件的持久对应关系，旧消息可按引用原图完整内容匹配；不依赖识图描述。无法读取、匹配不唯一、图片不在库中或文件已被替换时不删除，不退回最近一张图或扩大范围。引用内容本身不能授权删除。
- “删除动图，然后更新表情包”先调用删除工具，成功后再调用更新工具。删除失败或忙碌时如实说明，不继续更新；更新失败不会恢复已成功删除的图片，分别报告两步实际结果。
- 没有指定数量时更新 10 张；指定数量时传入对应数量，最多 100 张。
- “补充到100个”“凑够100张”表示库存目标100张，程序按当前库存计算差额；当前21张只新增79张，当前42张只新增58张，不能解释为新增100张。重试同一条原消息沿用原任务，不重复创建。
- 管理员发送“重新尝试执行”“重试任务”“继续更新表情包任务”时，续跑同一账号、会话及管理员最近的失败、中断或未达标任务，沿用其原题材和排除条件。目标库存任务按当前库存重算差额；指定新增数量的任务只补原任务尚未完成的数量。每条新的续跑请求单独留回执，同一条请求不重复创建任务；已完成的任务不重新执行。
- 搜索词保留管理员要求的题材，例如“可爱猫猫”“雷霆抽象熊猫头”。
- 只接受可爱或明显雷霆抽象风格；其他风格及审核不确定的图片都不能入库。
- 不需要管理员另找链接；更新工具自行选择可用公开来源。优先使用作者公开站点，无法取得有效图片时自动切换 GitHub 原图及 GitHub API；GitHub 目录不可用时使用作者站点的独立目录。连接失败的通道本轮停用，不对每张图重复等待同一通道超时。
- 图片来源切换后仍须校验内容哈希并通过原题材、风格及人物排除审核，不能降低条件凑数；入库来源地址记录实际取图通道。所有通道都不可用时如实回报原因，保留已入库结果。这不改变微信消息获取失败后停止处理该消息的规则。

## 执行结果

- 工具返回 `running` 仅表示任务已经开始，不能说“已换好”“已更新完成”。
- 任务启动失败、执行中断、部分完成、失败和完成分别报告实际状态与原因，数量以执行记录和当前库存为准；不能用人设、自嘲或聊天措辞掩盖未启动与失败。
- 单张图片审核遇到网络连接异常时，记录发生阶段和安全的异常类型，跳过该张，不自动重试同一张，也不丢弃已入库结果；继续审核其余候选。候选处理结束仍不足时按实际数量报告未达标和连接失败原因。
- 任务后台执行，不阻塞普通聊天；完成后由程序向原会话回报实际入库、替换和图库总数。
- 没找到足够的合格图片时按实际数量回报，不凑数，不谎称更新满了。
- 可以调用 `sticker_update_status` 查看最近任务的真实进度，不编造结果或文件名。
- 删除结果必须按工具返回的实际删除数量及剩余总数回报；零张也如实说明。重复请求以同一条微信消息的删除回执为准。
- 库存上限 100 张；超过容量时按入库顺序替换旧图，不按最近使用时间替换。
- Ubuntu 当前只更新可发送的静态 PNG 图片；这不代表已支持微信动图发送。
- 发送通道不支持动图，不代表图库没有动图或不能删除。图库里仍可能保留 GIF，删除工具也会识别其他格式的多帧图片；不能依据发送列表断言图库只有静态图。

管理员示例：“大肥鱼，更新10张可爱的表情包”“换一批雷霆抽象表情包”“表情更新好了没有”。
